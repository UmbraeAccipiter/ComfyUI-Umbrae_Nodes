=====================================================================
 WILDCARD PROCESSOR [UMBRAE] - SYNTAX CHEAT SHEET  (v0.9.4)
=====================================================================

Wildcard files are read from (priority order - a higher source wins):
  1. umbrae_nodes/wildcards/          (your files)
  2. Impact Pack's custom wildcards folder
  3. umbrae_nodes/wildcard_examples/  (shipped: aspect defaults + syntax
                                       examples; replaced on every update -
                                       copy a file into wildcards/ under the
                                       same path to edit it)
Press "Refresh Wildcards" on the node after editing files.


---------------------------------------------------------------------
 BASICS  (same as Impact)
---------------------------------------------------------------------
  __name__                 random line from name.txt
                           subfolder:  __folder/name__
                           YAML key:   __key/subkey__
  __name.txt__             same as __name__ (.txt / .yaml ignored)
  __folder/__              one line from EVERY file under folder/
                           (also what __folder__ does when there is
                           no folder.txt)   -> RELATIVE TAGS & FOLDERS
  __./name__  __../name__  inside a wildcard file: name next to this
                           file / one folder up -> RELATIVE TAGS & FOLDERS
  __col*__  __*/name__     pattern match across files / any depth

  {a|b|c}                  random pick each run
  {2::a|b|0.5::c}          weighted pick  (N:: = weight)

  {2$$a|b|c}               pick 2, joined by a space
  {1-3$$a|b|c}             pick 1 to 3
  {-3$$a|b|c}              pick up to 3
  {2$$, $$a|b|c}           pick 2, joined by ", "
  {3$$$, $ and $$__x__}    "x, y and z"  (last pair uses " and ")
  {2$$__file__}            pick 2 lines from a file

  {2$$3#__name__}          3#__name__ = three copies of __name__ as
                           options, so picks can repeat ("red red").
                           Outside { } it leaves literal | characters.

  # some line              comment (line removed)
  \{  \}                   literal braces
  \n                       line break in the output (also inside
                           wildcard file lines).  \\n = literal \n
  \&                       literal &
  \!                       literal !


---------------------------------------------------------------------
 RELATIVE TAGS & FOLDERS  (v0.8.8)
 Wildcard files can refer to each other without the full path from
 the wildcard root, so a pack keeps working when its folder is
 renamed or moved.
---------------------------------------------------------------------
  (inside a wildcard file)
  __./face__               face.txt (or face/) in the SAME folder as
                           the file containing the line
  __../scene__             scene.txt one folder UP (__../../x__ = two)
  __./outfit/__            every file under the outfit/ folder next
                           to this file
  __./person/jim.txt__     extensions are allowed and ignored

  Resolved when the file is LOADED (press Refresh Wildcards after
  moving files).  wildcards/CivitBobWildcrd/templates/main.txt with
  __../person/jim__ reaches wildcards/CivitBobWildcrd/person/jim.txt
  whatever the pack folder is called.
  YAML files: counted from the folder the .yaml file sits in.
  Typed in the prompt box (no file to count from): ./ = the wildcard
  root, so __./x__ is just __x__.

  FOLDER CALLS
  __person/outfit__ with no outfit.txt pools every line of every file
  under person/outfit/ and picks one (a 50-line file gets 50 chances,
  a 2-line file gets 2).  __person/outfit/__ (trailing slash) forces
  the folder even when outfit.txt exists; without it the file wins.

  RECURSION
  A file may call itself or its own folder.  A line already in use
  further up the same branch is never picked again, so recursion ends
  by itself instead of repeating one line until the 100-pass limit.
  If every line of a tag is already in use, the tag is removed and a
  warning is logged.
      story.txt:   hero, __./story__
                   villain, __./story__
                   the end.
      __story__  ->  "hero, villain, the end."  /  "the end."  / ...

  EXAMPLE LAYOUT  (shipped: wildcard_examples/example/portrait/,
                   call it with __example/portrait/portrait__)
      example/scene.txt
      example/portrait/portrait.txt
          a portrait of someone with __./face__, __./outfit/__, __../scene__
      example/portrait/face.txt
      example/portrait/outfit/casual.txt
      example/portrait/outfit/formal.txt


---------------------------------------------------------------------
 SWITCHES
 A switch stores a number; every {&name:...} group picks that
 option (counting from 1), so separate groups stay consistent.
---------------------------------------------------------------------
  {&gend=2}                define switch gend = 2 (removed from the
                           output; can sit anywhere in the text)
  {&gend={1|2}}            random value, picked once per run, the
                           same in every group
  {&gend={-::1^2}}         alternates 1, 2, 1, ... across runs
  {&gend:him|her}          option 2 -> "her"
  {&gend:{his|their}|her}  nested groups inside an option still work

  switches box (on the node):
    gend=2, hair=4    or    {&gend=2}{&hair=4}    or any mix
    (commas or new lines). Overrides same-named definitions in the
    prompt. Connect one text node to several processors to keep
    them all in agreement.

  - Out of range (including 0) -> last option + warning.
  - Undefined name or non-number value -> one random option is
    picked for that name (using the first group's N:: weights) and
    every group with that name uses it, so they stay consistent.
    A warning is logged when you press Run, so you can cancel
    before generating.
  - No count (2$$) or -:: / +:: prefix inside a switch group;
    N:: weights are ignored when the switch is defined.
  - Box typed, or connected from a Primitive / plain text node:
    resolved when you press Run. Connected from a node that
    computes text: resolved when the node executes
    (populated_text still shows the groups; the fallback and its
    warning also happen then).

  Example:
    box:     {&gend=2}{&hair=4}
    prompt:  {&gend=1}1{&gend:boy|girl}, {&hair:black|blond|brown|red} hair
    output:  1girl, red hair


---------------------------------------------------------------------
 OVERRIDES
 An override beats every ordinary definition of the same name - in
 the prompt or inside any wildcard file - wherever it sits.
---------------------------------------------------------------------
  {@!fcolor1=@fcolor2}     variable override: fcolor1 takes
                           fcolor2's value, even when a wildcard
                           file defines both
  {@!fcolor1={teal|olive}} any variable value works: text, {a|b},
                           __file__, #a
  {&!gend=2}               switch override: beats {&gend=...} in
                           the prompt or in files

  - Switch priority: switches box > {&!...} > {&...}.
  - The same override defined twice: the later one wins (+warning).
  - A reference to a variable that is never defined is left as-is.

  Example:
    file:    {@fcolor1={blue|navy}}{@fcolor2={red|crimson|scarlet}}
             a {@fcolor1} shirt with {@fcolor2} trim
    prompt:  {@!fcolor1=@fcolor2} __outfit__
    output:  a red shirt with red trim

  PROTECTED OPTIONS AND =r=  (v0.8.9)
  Mark options in a file's definition with -=...=- ; an @! override
  then only touches the others.  One pair may wrap several options.
  {@shade=-=light=-|dark|-=bright=-|dull}   light, bright protected
  {@shade=-=light|dark|deep=-|rich|bright}  one pair, three protected
  {@!shade=shining}        PER DRAW: every unprotected option becomes
                           shining (own weight kept); it shows only when
                           such an option is drawn.  Other odds unchanged.
  {@!shade=r=shining}      REPLACE FIRST: all unprotected options become
                           ONE shining entry before the draw, with the
                           highest weight of those it replaced.
  Example, 7 options, 3 protected: plain = shining 4 in 7, r = 1 in 4.
  - No protected option: both forms replace the whole value (as before).
  - The file's definition must be a plain a|b|c list.
  - Protected text is also shielded from {!..} replacements.


---------------------------------------------------------------------
 PINS  (v0.8.9)     {&=CHOICE:TARGET}
 Force a choice without editing any file.
---------------------------------------------------------------------
  {&=2:@gend}              variable gend takes its 2nd option
  {&=red:__fabric_colors__}  every draw from fabric_colors takes the
                           first line containing "red"
  {&=1:him|her}            every group with exactly the options
                           him|her (any case) takes option 1
  CHOICE: number = Nth option / line; text = first option / line that
  contains the word.  No match: warning + normal random draw.
  Short tag names match like normal tags.  Pins beat random picks;
  @! and &! overrides still win; anything inside {-=..=-} is skipped.
  Work in the prompt and in files; removed from the output.  Not read
  from the switches box.


---------------------------------------------------------------------
 TEXT REPLACEMENT
 Runs LAST. Whole words / phrases only ("there" is never touched by
 her). All replacements happen in one pass: swaps work, nothing is
 replaced twice.
---------------------------------------------------------------------
  {!she=he}                any case matches; case follows the text:
                           she -> he, She -> He, SHE -> HE
  {!!She=Mary}             exact case only: replaces "She", leaves
                           "she" and "SHE"; inserted as written
  {!!!mod=LoRa}            any case matches (mod, Mod, MOD, mOd); the
                           replacement is inserted exactly as written
  {!!!!mod=LoRa}           exact case only, inserted as written; same
                           as {!!mod=LoRa} (alias)
  {!her=him}{!him=her}     swap
  {!long red hair=short black hair}
                           phrases work
  {!cat={dog|fox}}         replacement may contain syntax,
                           resolved once per run

  Case rules for !:
    all lowercase      -> lowercase
    First capitalised  -> First capitalised
    ALL CAPS           -> ALL CAPS
    Every Word Capped  -> Every Word Capped (phrases)
    anything mixed     -> as written
  Note: a lowercase match lowercases the replacement, so
  {!she=Mary} turns "she" into "mary" - use {!!she=Mary} for names.

  - Flags: !  any case in, case follows out   !! / !!!!  exact case
    in, as written out   !!!  any case in, as written out.
  - !! beats the others on the same word; then a longer phrase wins;
    then !!! beats !.
  - Can sit in the prompt or in a wildcard file. Same find defined
    twice: the later one wins (+warning). Removed from the output.

  PROTECTED TEXT  (v0.8.9)
  {-=man=-}                the text is written as-is; NO {!..} / {!!..}
                           replacement touches it.  The {-= =-} wrapper
                           is removed.
  - Contents still resolve first ({-=a {red|blue} man=-},
    {-=__./who__=-}); only the replacement step skips them.
  - With {!man=woman} in the prompt, "the man" -> "the woman" but
    {-=man=-} stays "man" (mannequin, fixed title, quoted word).
  - Works in the prompt and in wildcard file lines.

  GENDERED WILDCARD TEXT
  Write gendered words once as switches, set the gender in one place:
      {&gend:he|she} wears {&gend:his|her} jacket   (in a wildcard file)
      {&gend=2}                                     (prompt / switches box)
      {&!gend=1}                                    (override)
  Keep option order the same everywhere (1 = male, 2 = female).  A
  single-gender line can skip the switch and be flipped with
  {!she=he}; wrap words that must never flip in {-=...=-}.


---------------------------------------------------------------------
 VARIABLES
---------------------------------------------------------------------
  {@hero=__emotions__}     define once; resolved once per run
  {@hero}   or   @hero     reuse the same value
  {@b=#a}                  pick from a's original list, excluding a
  {@c=#a,#b}               ... excluding a and b


---------------------------------------------------------------------
 PERSISTENT SELECTION
 Remembered between runs. Cleared by the "Reset cycles & counter"
 button or a ComfyUI restart.
---------------------------------------------------------------------
  {a^b^c}                  shuffled bag: every item once before any
                           repeat
  {-::a^b^c}               written order: a, b, c, a, b, ...
  {-::__file__}            written order through a file's lines

  {+::a|b|c}               random, never the same item twice in a row
  {3+::a|b|c|d|e}          random, none of the last 3 items used
  {3$$3+::a|b|...|j}       3 per run, none of the previous run's 3
  {2+::a^b^c^d}            shuffled bag; a new bag never starts with
                           any of the last 2 items
  {2+::__file__}           no-repeat pick from a file

 NOT persistent (this run only):
  {-::a|b|c}               always the first item -> "a"
  {2$$-::a|b|c}            first 2 in written order -> "a b"


---------------------------------------------------------------------
 PREFIX RULES  (-::  and  N+::)
---------------------------------------------------------------------
  - Goes right after "{", or right after the count part
    (2$$  /  2$$, $$  /  3$$$, $ and $$).
  - One prefix per group.
  - \+::  and  \-::  are plain text, not prefixes.
  - Weights (N::) still count with +::, are ignored with -::.
  - If the history would leave too few choices, it forgets the
    oldest entries first. It never errors and never returns nothing.
  - The pick happens when the run is QUEUED.
  - A nested random group, e.g. {2+::a|{b|c}}, starts a fresh
    history whenever the inner pick changes.


---------------------------------------------------------------------
 ASPECT RATIO  (v0.8.7)
---------------------------------------------------------------------
  The node reads the image size from the workflow and adapts the text
  to it. Connect the LATENT the image is made from (or width + height
  ints) to the node's inputs; nothing needs typing.

  [[aspect]]               inserts a description of the connected image's
                           orientation on its own line: one random line
                           from __aspect/[orientation]__, i.e.
                           aspect/horizontal, aspect/vertical or
                           aspect/square. Defaults ship in
                           wildcard_examples/aspect/; copy one into
                           wildcards/aspect/ to edit it
  [orientation]            token -> horizontal / vertical / square (W = H)
  [ratio]                  token -> nearest common ratio of the connected
                           size, e.g. 1328x752 -> 16:9 (exact fraction
                           when none is within 3 %)
  [width]  [height]        token -> the connected pixel size
  [3:4]                    typed override, used only when nothing is
                           connected; removed from the output.
                           [[3:4]] = request + override in one

  - Tokens are filled last, anywhere: prompt and wildcard file lines.
    Unknown [words] are left as typed.
  - W > H horizontal, W < H vertical, W = H square.
  - Requests work wherever they appear (switch option, variable, file line).
  - Inside the lines of aspect/*.txt write [orientation] for the word
    ("The crop is [orientation]"). A [[aspect]] there is read as
    [orientation] too, so it never nests another line (v0.8.9).
  - The size is often only known when the node runs (a latent, or a
    width/height computed by another node). Then [[aspect]] and the tokens
    stay as typed in populated_text at queue time and are resolved during
    the run; populated_text is updated afterwards.
  - Nothing connected and no typed override: [[aspect]] inserts nothing
    and the tokens use 1:1 (warning logged).
  - Missing aspect wildcard: nothing inserted (warning logged).


---------------------------------------------------------------------
 SYNTAX COLOURS  (v0.9.4)
---------------------------------------------------------------------
  The wildcard_text box colours its syntax as you type, so wildcards,
  variables and brackets stand out. It only changes how the text is
  drawn - the prompt itself is never touched. populated_text is not
  coloured.

  __name__             tag: the name and its __ ends are two blues; a
                       tag that matches no wildcard turns red
  {@x}  @x             variable; an override {@!x} has its own colour
  {&x}                 switch; an override {&!x} and a pin {&=2:x}
                       each have their own colour
  {!a=b}               replacement (also {!!a=b} {!!!a=b} {!!!!a=b})
  {-=x=-}              protected text
  [[aspect]]  [ratio]  aspect request and tokens
  2::  2$$  -::  +::   weights, counts and persistent prefixes
  |  ^                 option separators
  \{  \n               escapes (literal text)
  # line               comment line

  - A brace takes the colour of its group's kind ({@x} orange, {&x}
    violet ...). Plain {a|b} groups cycle four colours by nesting
    depth. Closing braces are coloured like their opener (setting).
  - Options inside a group: every second option gets another colour
    (default). Setting: alternate / none / cycle (4 colours) / tint
    (background).
  - Caret touching a { } brace: its partner lights up. Caret inside a
    tag, variable or switch: every other use of that name lights up.
  - Red is used only for warnings: an unmatched { or }, an unmatched
    [[ or ]], and a __tag__ that matches no wildcard.
  - The unknown-tag check asks the server how the engine would
    resolve the tag (relative and folder tags included; patterns with
    * are not checked) and follows Refresh Wildcards within a few
    seconds.
  - Settings -> Umbrae -> WildcardHighlight: on / off, colour
    closers, partner on caret, same-name highlight, unknown-tag
    warning, option mode, "Reset all colours to" dark or light, and
    one colour picker per category.
  - Default: dark palette (light tones for dark mode). Choose light
    to reset every picker to the dark-tone palette for a light theme.
    Colours are shared by every wildcard processor.
  - If the colours ever fail to line up with the text box they switch
    themselves off for that box (a warning appears in the browser
    console) and the plain box is restored.


---------------------------------------------------------------------
 NODE CONTROLS
---------------------------------------------------------------------
  mode
    populate   fills populated_text when you press Run
               (read-only, but you can select and copy it)
    fixed      uses populated_text exactly as written
    reproduce  pick by hand: uses populated_text once, then
               switches back to populate

  Loading an image
    The node comes back in populate mode, so it regenerates from
    wildcard_text. The image's exact prompt is shown in
    populated_text - copy it before running, or switch to fixed
    to re-create it exactly.

  seed connected to a node that computes it
    The prompt is resolved when the node runs (populated_text
    updates then; a warning is logged).

  runs
    Queue the workflow X times. The next run is queued only after
    the previous one finishes. Cancel / interrupt / error stops the
    series; switching workflow tabs mid-run also stops it.
    Outputs: run_index (1..X) and runs_remaining.
    Do NOT also set ComfyUI's batch count - they multiply.

  Search wildcards...   (v0.8.9)
    Popup that filters the whole list as you type (every word must
    match the name or folder).  Click ticks several entries; Enter
    inserts the ticked ones (or the highlighted one) into
    wildcard_text.  Ticks stay while you change the search.  The
    right side previews the first lines of the highlighted wildcard.
    YAML wildcards are listed under their file's folder.

  Preview prompt   (v0.8.9)
    Resolves the current wildcard_text with the node's seed and
    switches without running.  Roll again = next seed.  Never
    advances the node's ^ / -:: / +:: cycles.

  switches box
    Keeps a small fixed height, so a taller node gives its room to
    the prompt boxes.

  Reset cycles & counter
    Restarts this node's bags, orders, histories and countdown.
    Stopping a series does NOT reset these - press Reset.

  switches
    Switch values - see SWITCHES.

  Refresh Wildcards
    Reloads wildcard files from disk.

 EXAMPLE: 28 expressions, one each, in list order, then stop
---------------------------------------------------------------------
  1. emotions.txt (a short one ships in wildcard_examples/; your own
     copy in umbrae_nodes/wildcards/ replaces it),
     one expression per line.
  2. wildcard_text = {-::__emotions__}
  3. runs = 28
  4. Press "Reset cycles & counter", then press Run once.
